# 文件闪传系统 (QuickShare) — 项目说明文档

## 一、项目概述

QuickShare 是一个**端到端加密的临时文件传输系统**，基于 Web 构建，适用于讲座、会议、展览、临时协作等场景——无需互加微信好友，也无需上传至云盘，即可在多人之间安全、快速地传输文件。

### 核心特性

| 特性 | 说明 |
|------|------|
| **端到端加密** | 文件在客户端加密后传输，服务器无法解密文件内容 |
| **临时性** | 文件有明确的过期时间，到期自动清理 |
| **12位取件码** | 简洁的分享机制，接收者凭码取件 |
| **文件去重** | 相同文件重复上传可复用缓存，秒级完成 |
| **下载次数限制** | 支持限制每个取件码的下载次数 |

## 四、核心机制详解

### 4.1 端到端加密体系

QuickShare 采用**两层密钥**架构，确保服务器永远无法解密文件内容：

```
第一层：文件加密密钥 (File Encryption Key)
  - 客户端随机生成，AES-GCM 256位
  - 直接加密/解密文件块
  - 永不传输到服务器

第二层：密钥码派生密钥 (Key-Code Derived Key)
  - 从取件码后6位密钥码通过 PBKDF2 派生 (100000次迭代, SHA-256)
  - 用于加密/解密第一层的文件加密密钥
  - 服务器不接触密钥码（只接收前6位查找码）

传输到服务器的唯一密钥数据：
  → 加密后的文件加密密钥 (已用派生密钥加密)
```

**上传流程：**
```
客户端生成文件加密密钥
  → 用文件加密密钥加密每个文件块
  → 用密钥码派生密钥加密文件加密密钥
  → 将加密后的密钥发送到服务器存储
```

**下载流程：**
```
服务器返回加密后的密钥
  → 客户端用密钥码派生密钥解密
  → 得到文件加密密钥
  → 用文件加密密钥解密文件块
```

### 4.2 12位取件码机制

取件码 = **6位查找码 + 6位密钥码**

| 部分 | 位置 | 存储位置 | 用途 |
|------|------|----------|------|
| 查找码 | 前6位 | 服务器数据库 | 定位取件码记录，查询文件元数据 |
| 密钥码 | 后6位 | 仅客户端 | 派生解密密钥，服务器永不接触 |

**安全性保障：** 即使数据库完全泄露，攻击者也无法解密文件内容（缺少密钥码部分）。

### 4.3 标识码映射机制

同一文件被多次分享时，所有取件码映射到同一个"标识码"，共享文件缓存：

```
文件A第一次上传 → 取件码 ABC123 → 标识码 = ABC123 (原始)
文件A再次分享   → 取件码 XYZ789 → 映射到标识码 ABC123

缓存访问：
  ABC123 → 标识码 ABC123 → 文件块缓存 ✓
  XYZ789 → 标识码 ABC123 → 文件块缓存 ✓ (共享)
```

**延时机制：** 新取件码复用文件缓存时，缓存的过期时间自动延长到所有取件码中最晚的那个。

### 4.4 双池加速机制

| 池 | 用途 | 清理策略 |
|----|------|----------|
| **上传池** | 暂存正在上传的文件块（内存操作），全部完成后批量写入主缓存 | 超过1小时未完成自动清理 |
| **下载池** | 预读取后续10-25个块到内存，加速顺序下载 | 超过10分钟未访问自动清理 |

### 4.5 文件去重机制

- 前端对**原始文件（未加密）**计算 SHA-256 哈希
- 后端使用 HMAC-SHA256 生成去重指纹：`HMAC(user_id + 文件哈希, 服务器盐)`
- 相同用户 + 相同文件 → 复用缓存，秒级完成（无需重新加密上传）

**设计要点：** 不使用加密文件哈希（密钥变化会导致哈希变化，无法去重）。

### 4.6 定时清理机制

系统启动时启动后台异步任务，周期性地清理过期数据：
- 数据库中的过期取件码记录
- Redis/内存中的过期文件块、文件信息、加密密钥
- 过期的映射关系
- 上传池和下载池中的废弃数据

### 4.7 用户认证 (JWT)

- 注册/登录时，密码在**前端**使用 SHA-256 哈希后传输
- 服务端使用 `python-jose` 签发 HS256 JWT 令牌
- 发送者必须登录，接收者可匿名访问
- 无状态验证，适合水平扩展

## 五、API 路由结构

```
GET  /                        欢迎页

# 认证

POST /api/v1/relay/codes/{code}/store-encrypted-key 存储加密密钥

POST /api/v1/relay/codes/{code}/download-chunks      批量下载加密块
POST /api/v1/relay/codes/{code}/download-complete    通知下载完成
DELETE /api/v1/relay/codes/{code}/chunks            删除文件块

# 健康检查
GET  /health                   服务健康状态
GET  /status                   服务运行状态
```

## 八、安全设计总结

| 层面 | 措施 |
|------|------|
| **传输层** | HTTPS + TLS 加密通道 |
| **存储层** | 服务端只存储加密后的文件块和加密后的密钥 |
| **密钥管理** | 解密密钥的后6位永不传输到服务器 |
| **去重隐私** | 数据库不存储明文文件哈希，使用 HMAC 加盐处理 |
| **用户隔离** | 不同用户的相同文件独立存储，缓存键包含用户ID |
| **访问控制** | 上传需登录 (JWT 认证)，下载凭取件码 |
| **过期清理** | 文件到期自动清理，不残留敏感数据 |
